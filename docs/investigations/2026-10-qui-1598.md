# Shared stream queues (`QUI-1598`)

All 18 first-pass matrix cells pass on this host at both read counts.
A repeat with the final test now has a long-running 32-session, 128-read cell with 32 connections.
Another process now uses device 0. Root-cause confirmation is in progress, and this work adds no fix.

## Reproduction

The ticket reports 48 concurrent MSA sessions on an RTX A4000 with `CUDA_DEVICE_MAX_CONNECTIONS=32`.
Each session receives one job with 2,108 nodes, 8,192 sweeps, and 64 reads.
The ticket reports zero results after seven hours.
Its 128-read control completes on another GPU in about two minutes.

The ignored test `tests/concurrent_sessions_gpu.rs` uses the degree-4 ring from the task brief.
Each session owns two CUDA streams and receives one job through a closed input channel.
The test requires every `run_stream` call to return a successful result before a shared 900-second deadline.
It prints the count and elapsed time before it fails on a hang.

## Hypotheses

H1: stream queues can put a transfer behind another session's persistent kernel.
The resulting cycle prevents the exit writes from reaching either kernel.
H1 predicts a hang risk when the stream count exceeds the connection count, at both read counts.

H2: the one-word MSA path itself stops responding.
A hang with one session and 64 reads would make H2 the lead hypothesis.

The 128-read path takes longer than the 64-read path in all nine pairs, but both finish.
The first-pass results do not confirm H1 or H2.
They do not explain the original ticket's 128-read control.
The test starts host threads without a barrier that forces all kernels to run at once.
Its graph has degree 4 and unit couplings. The ticket's actual graph is not part of this test.
Passing these short runs does not rule out a queue cycle with another workload or driver.

## Validation

The full host suite passes. Formatting and Clippy pass with warnings treated as errors.
The check runs through `make PWD=/zfspool/quip-mining/quip-solver-cuda-wt-qui-1598 check`.
The check uses `RUN_CI` to add a Docker name for cleanup.
It also installs Rust version `1.97.1` before the format and lint checks.
The override uses the same image and absolute mounts as the default target.
The repository's Rust toolchain and dependencies stay unchanged.

A separate deadline check sets `QUIP_SESSIONS=1`, `QUIP_READS=64`, and `QUIP_DEADLINE_SECS=0`.
It fails as expected with 0/1 sessions and `sessions hung`, then exits with code 101.
The assertion prints after 91.693 microseconds. The full test exits after 1.20 seconds.
This check proves that an expired deadline fails the test. It does not reproduce the ticket's hang.
